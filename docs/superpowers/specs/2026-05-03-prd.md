# SiTED 产品需求设计文档（PRD）

**项目**: SiTED - Silicon Trusted Engineering Dojo  
**版本**: 1.0  
**日期**: 2026-05-03  
**状态**: 可评审版，作为 UI/UX 设计与开发计划输入  

---

## 1. 产品概述

SiTED 是面向公司内部研发人员的 TPC 认证训练平台，帮助用户围绕编程知识、安全质量隐私、重构知识三类题库完成日常练习、错题复习、收藏沉淀和模拟考前检验。

产品主链路：

1. 用户在公司内网打开站点，系统按 IP 自动识别身份。
2. 用户按科目、语言、级别、题型和关键词筛选题目，关键词可匹配标签。
3. 用户进入练习，并可在同一页面切换练习模式或背诵模式。
4. 系统在练习模式下沉淀练习记录和错题；题库收藏单独沉淀重点题目；背诵模式只读取答案和解析。
5. 用户通过模拟考试检验准备情况。
6. 题库管理员维护题目，系统管理员维护 IP 权限和基础运维配置。

产品目标：

- 降低内部研发人员练习 TPC 选择题的进入成本。
- 提供稳定、清晰、高效率的刷题与复习体验。
- 支持题库的日常维护、导入导出和基础运营统计。
- 控制首版复杂度，优先完成可用的训练闭环。

## 2. 已确认前提与产品边界

### 2.1 已确认前提

| 主题 | 结论 | 产品影响 |
|---|---|---|
| 用户身份 | 一个可访问 IP 只对应一个稳定使用者，不存在多人共享同一出口 IP | 使用 IP 作为用户身份和权限识别依据 |
| 真实 IP 获取 | 仅信任受控 Nginx 的 `X-Forwarded-For`，否则使用连接 IP | 后端需要配置可信代理，不接受任意客户端伪造头 |
| 终端范围 | 主要使用桌面 Chrome/Edge，不存在移动端使用场景 | UI 优先桌面效率，不做移动端适配 |
| 题库规模 | 预计 5 万题以内 | PostgreSQL 普通索引和简单关键字查询即可支撑 P0 |
| 图片依赖 | 少量题目需要图片，批量导入以文本题为主 | P0 支持手动上传图片；ZIP 媒体包导入导出进入 P1 |
| 模拟考次数 | 不限制次数，每次考试独立记录 | 不做报名、限次、锁题、只保留最高分等考试管理能力 |
| 多选评分 | 必须完全匹配正确选项才算正确 | 评分逻辑统一，不做部分得分 |
| 题目删除 | 题目只归档，不物理删除 | 保留历史练习记录和模拟考复盘完整性 |
| 题目版本 | 不做题目版本管理；模拟考保存试卷快照 | 普通练习查看题目当前版本，模拟考复盘查看当时快照 |
| 数据保留 | 个人训练数据长期保留，管理员可清空 | 不做自动清理策略 |
| 暗色主题 | 暗色主题已作为 P0+ 体验增强交付 | 默认仍为 Light 主题，用户可在前端切换 Dark 主题并持久化到当前浏览器 |

### 2.2 不做范围

- 不做注册、密码登录、短信、邮箱或单点登录。
- 不做复杂组织架构、团队排名、积分、徽章或证书。
- 不做多语言国际化，界面语言固定为中文。
- 不做面向公网的安全模型，部署边界限定为公司内网。
- 不做自定义角色和自定义权限组合。
- 不做全文搜索引擎、分布式文件存储、复杂服务端缓存或消息队列；前端允许使用会话内存缓存优化页面切换体验。

## 3. 用户与权限

### 3.1 角色定义

| 角色 | 内部值 | 设置方式 | 能力 |
|---|---|---|---|
| 学习者 | `learner` | 默认角色 | 题库浏览、题库练习、模拟考试 |
| 题库管理员 | `content_admin` | 系统管理员按 IP 绑定 | 学习者能力 + 题库维护、导入导出、运营看板 |
| 系统管理员 | `system_admin` | 环境变量 `SYSTEM_ADMIN_IPS` | 题库管理员和学习者能力 + 系统配置、数据清空 |

角色规则：

- 系统只提供固定角色，不提供自定义角色页面。
- 数据库不存储权限数组，后端根据角色枚举推导权限。
- 系统设置页的权限范围基于后端返回的 `permissionKeys` 聚合为能力分组展示，不展示不可单独配置的细粒度权限项。
- 系统管理员只能由环境变量指定，不允许在前端移除自身系统管理员身份。
- 系统设置页只允许新增和删除数据库中的 IP 固定角色绑定；`SYSTEM_ADMIN_IPS` 来源的系统管理员绑定展示为系统配置来源，不可删除。

能力分组：

| 能力分组 | 覆盖的 `permissionKeys` |
|---|---|
| 题库浏览 | `question:browse` |
| 题库练习 | `practice:use`、`recite:use`、`mistake:review`、`bookmark:use` |
| 模拟考试 | `exam:use` |
| 题库维护 | `question:create`、`question:edit`、`question:archive` |
| 导入导出 | `question:import`、`question:export` |
| 运营看板 | `stats:view_basic` |
| 系统配置 | `ip_role:write`、`audit:view`、`config:reload` |
| 数据清空 | `data:clear` |

### 3.2 身份识别流程

1. 用户访问任意页面。
2. 后端从连接信息或可信代理头中解析真实 IP。
3. 后端校验 IP 是否命中 `ALLOWED_CIDR`。未命中返回 `403`。
4. 若 IP 命中 `SYSTEM_ADMIN_IPS`，身份为 `system_admin`。
5. 否则查询 `IpRoleBinding`，命中则使用绑定角色。
6. 若 IP 首次出现，创建或更新 `Visitor`，身份为 `learner`。
7. 前端启动时调用 `GET /api/me`，获得当前 IP、角色和可访问导航项。

身份设计：

- 每次 API 请求都由后端重新解析 IP 和角色。
- 前端不保存登录凭证，不实现凭证刷新链路。
- 角色变更在下一次请求生效，不需要用户登出。

## 4. 题库领域

### 4.1 科目、语言与级别

| 科目 | 内部值 | 语言 | 级别 |
|---|---|---|---|
| 编程知识 | `programming` | C、C++、Python、Java | 入门、工作、专业 |
| 安全质量隐私 | `security_privacy` | C、C++、Python、Java | 工作、专业 |
| 重构知识 | `refactoring` | 不区分语言 | 专业 |

字段定义：

| 概念 | 字段 | 说明 |
|---|---|---|
| 科目 | `subject` | `programming` / `security_privacy` / `refactoring` |
| 语言 | `language` | `c` / `cpp` / `python` / `java`，重构题为空 |
| 级别 | `level` | `entry` / `working` / `professional` |
| 题型 | `type` | `single` / `multiple` / `judgment` |
| 知识点 | `tags` | 自由标签，去重、去空格 |

合法题源组合共 21 种：

- 编程知识：4 种语言 x 3 个级别 = 12。
- 安全质量隐私：4 种语言 x 2 个级别 = 8。
- 重构知识：1 种 = 1。

后端必须在题目发布、导入和模拟考组卷时校验组合合法性。

### 4.2 题型规则

| 题型 | 内部值 | 选项数量 | 正确选项数量 | 判定 |
|---|---|---:|---:|---|
| 单选 | `single` | 3-6 | 1 | 选择完全匹配 |
| 多选 | `multiple` | 3-6 | 2-N | 选择完全匹配 |
| 判断 | `judgment` | 2 | 1 | 按单选存储，UI 展示为判断题 |

新增题目编辑器规则：

- 单选题和多选题默认生成 A-D 四个空选项，允许增减到 3-6 个选项。
- 判断题固定 A/B 两项，文本为“正确 / 错误”，不显示增减选项。
- 单选题和判断题只能保留 1 个正确答案；多选题发布时至少需要 2 个正确答案。
- 删除选项后按 A、B、C 顺序重新编号，并同步正确答案 key。

选项结构：

```json
[
  { "key": "A", "text": "选项文本", "isCorrect": false },
  { "key": "B", "text": "选项文本", "isCorrect": true }
]
```

### 4.3 内容渲染

P0 统一使用 Markdown 承载题干和解析。

| 字段 | 能力 |
|---|---|
| `stemMd` | Markdown、同源图片、fenced code |
| `explanationMd` | Markdown、同源图片、fenced code |
| `options[].text` | 纯文本 |
| `memo` | 纯文本，一句话速记 |

安全约束：

- Markdown 由服务端 sanitize 后返回。
- 图片只允许 `/uploads/...` 同源地址。
- 外链图片、`script`、`iframe`、内联事件和 `javascript:` 协议全部移除。
- 代码块通过 Markdown fenced code 渲染。

### 4.4 题目状态

| 状态 | 内部值 | 行为 |
|---|---|---|
| 草稿 | `draft` | 仅管理员可见，不进入练习和考试 |
| 已发布 | `published` | 可被学习者使用 |
| 已归档 | `archived` | 不再进入新练习和新考试，历史记录仍可查看 |

## 5. 功能范围

### 5.1 P0 必须交付

| 模块 | 范围 |
|---|---|
| 身份与权限 | IP 识别、CIDR 白名单、固定角色、IP 角色绑定。前端展示当前 IP 与角色，不额外提示 CIDR 命中细节。系统设置中使用可读角色名称，并将 `permissionKeys` 聚合为能力分组展示，避免直接暴露抽象内部值和不可配置的细粒度权限。 |
| 首页 | 通过真实接口展示今日训练、核心指标、训练日历、题源可练习状态和推荐工作流；无记录时显示零值和真实空状态，不回退演示数据。训练日历按真实月份渲染，支持月份切换，周一到周日排列，并使用固定 6 周网格避免 4/5/6 行月份导致页面高度跳变。 |
| 题库浏览 | 支持科目、语言、级别、题型和关键字筛选；关键字可匹配标签，筛选条件在同一浏览器本地保留，列表展示所有符合条件的已发布真实题目。科目在筛选与展示中使用“科目X（名称）”形式，级别统一带“级”后缀。右侧题目预览展示选中真实题目的公开详情，不暴露正确答案。 |
| 练习 | 单题作答、即时反馈、解析、上一题、下一题、快速跳题和记录作答。练习页内提供“练习 / 背诵”双模式：练习模式提交后写记录，答错后允许改选并再次提交；背诵模式直接查看答案和解析，不写训练记录。 |
| 复习 | 包含错题、收藏、模拟考记录三个真实可切换标签。去除无效说明文案，优化表格列宽、操作列对齐、分页控件间距和状态颜色；未掌握与已掌握必须使用不同颜色。记录标签只展示模拟考复盘入口，不展示单题练习记录。 |
| 模拟考 | 首屏先展示进行中考试或最近已交卷复盘；没有可恢复考试时展示题源选择页，用户点击“开始模拟考”后才组卷。考场提供答题卡、提交答案、标记疑问、交卷确认和复盘；复盘展示正确率、正确/错误题数和每题对错，重新模拟考回到题源选择页。考试标题中的题源使用科目编号、语言和级别，不展示冗长科目名称。 |
| 题目管理 | 新增、编辑、发布、归档、实时预览。编辑器显示全部语言、全部级别和单选题/多选题/判断题；题干标签为“题干（支持 Markdown 语法）”；选项每行一个，支持单选/多选 3-6 项增减和判断题固定 A/B 录入；保存草稿仅写入本地草稿，发布前做前端校验并展示顶部 toast；正确答案行有持久高亮和切换动画；实时预览区域扩大，按 Markdown 代码块样式渲染代码关键字，并展示当前解析。 |
| 导入导出 | JSON 题库导入导出，导入前验证报告。导入错误需要能定位到题目和字段。 |
| 管理能力 | 运营看板通过 `/api/admin/stats` 展示真实运营数据，包括当前题库数量、题量分布、Top10 低正确率题目、今日访问用户、今日练习题数和今日模拟考次数，不回退演示数据。Top10 低正确率题目必须基于实际 `PracticeAttempt` 聚合计算，不依赖题目表冗余统计字段。题库统计和训练统计区域宽度对称；训练趋势拆分为三个独立近 7 天坐标图，分别展示访问用户、练习题数、模拟考次数，不混用数量级。系统设置中 IP 固定角色管理位于高风险操作上方，数据清空需确认短语并写入审计日志。 |
| 前端体验与加载策略 | 全局设计系统覆盖 Light/Dark token、字体层级、阴影、边框、间距、状态色、图表色和焦点态；默认 Light 主题，Dark 主题作为可切换增强项写入当前浏览器。按钮、选项、卡片、表格、Toast、Dialog、答题反馈和图表 hover 使用局部动作反馈，遵守 `prefers-reduced-motion`。路由层不得使用阻塞式整页退出动画；静态页切换立即渲染，数据页使用会话内存 stale cache，重复访问优先显示上次成功数据并后台刷新。 |

- 图片上传体验增强和 ZIP 媒体包导入导出。
- 个人数据跨 IP 导出/导入。

导航规则：

- 普通学习者不展示管理导航。
- 题库管理员展示题目管理和运营看板。
- 系统管理员展示全部管理入口。
- 侧边栏只展示“练习”入口，不再单独展示“背诵”；背诵作为练习页内模式存在。
- 用户直接访问无权限页面时展示权限不足页，不渲染目标页面内容。

## 7. 核心业务流程

### 7.1 首次访问

1. 用户打开站点。
2. 若 IP 不在 `ALLOWED_CIDR`，显示无权限页面。
3. 若 IP 在内网范围内，后端创建或更新 `Visitor`。
4. 前端展示首页，并按角色展示可访问导航。

首页 P0 信息：

- 当前身份：IP、角色。
- 今日练习：作答数、正确率，来源于当前访问者真实练习记录。
- 错题复习：未掌握错题数量。
- 训练日历：按真实月份展示每日训练状态。
- 题库覆盖：展示各科目可练习组合概览。
- 模拟考：最近一次成绩、进行中状态或暂无记录空状态。

### 7.2 题库浏览到练习

1. 用户在题库页选择科目、语言、级别。
2. 可选过滤题型和关键字；关键字同时匹配题目标签。
3. 列表展示所有符合条件的已发布真实题目，不使用 mock fallback。
4. 系统把当前筛选条件写入同一浏览器的本地存储，用户切换页面或刷新后回到题库仍恢复上次筛选。
5. 用户选择“按当前筛选练习”。
6. 系统把当前筛选条件传入 `/practice`，用户可在练习页切换练习或背诵模式。

空状态：

- 当前筛选无题：提示调整筛选或联系题库管理员。
- 题量不足以开始模拟考：提示缺少的题型和数量。

### 7.3 练习

1. 系统从当前筛选或 `questionId` 加载已发布真实题目序列。
2. 用户在“练习 / 背诵”模式之间切换。
3. 练习模式下，用户选择答案后点击“提交答案”。
4. 后端校验答案并写入 `PracticeAttempt`。
5. 若答错，写入或更新 `Mistake`。
6. 若答对且该题在未掌握错题中，`consecutiveCorrect += 1`。
7. 连续答对 3 次后标记为已掌握。
8. 前端展示回答正确/回答错误、正确答案、解析和速记。
9. 用户可上一题、下一题或通过快速跳题切换题目。

规则：

- 答错后允许继续改选并再次提交；每次提交都写入真实练习记录。
- 改选后清空旧的对错高亮和解析，重新提交后再展示新的结果。
- 当前页面会话内按题目保留已选答案和最近提交结果；刷新页面后不要求恢复。
- 未提交离开页面不写练习记录。
- 背诵模式直接调用含答案详情，展示答案和解析，不写练习记录，也不影响错题掌握状态。

### 7.4 复习

复习页包含三个标签：

| 标签 | 内容 | 主要操作 |
|---|---|---|
| 错题 | 未掌握和已掌握题目 | 重练、标记掌握、取消掌握、移除 |
| 收藏 | 收藏题目 | 练习、背诵、编辑备注、管理标签、取消收藏 |
| 记录 | 模拟考记录 | 查看复盘 |

错题按最近答错时间倒序。三个标签均使用前端分页，默认每页 10 条，支持切换每页 10 / 20 / 50 条；删除错题或取消收藏后必须夹紧当前页，避免停留在空页。

### 7.5 模拟考

1. 前端进入 `/exam` 后先查询考试列表。
2. 若存在进行中考试，直接恢复考场。
3. 若存在最近已交卷考试，展示复盘状态。
4. 若没有可恢复考试，展示未启动模拟考页面，用户选择科目、语言、级别。
5. 用户点击“开始模拟考”后，后端按题源范围和卷面配置组卷。
6. 题量不足时返回明确缺口。
7. 前端进入考场，展示倒计时、题目和答题卡。
8. 用户选择答案后点击“提交答案”，系统保存答案并前进到下一题。
9. 用户交卷前显示确认；如仍有未答题，明确提示未答数量。
10. 用户交卷或倒计时结束后，后端评分并批量写入错题。
11. 前端进入复盘页，展示考试总结果、每题正确/错误状态和当前题解析。
12. 用户点击“重新模拟考”时返回题源选择页，不直接创建新考试。

考试规则：

- 同一用户同一时间只允许一个进行中考试。
- 倒计时以服务端 `deadlineAt` 为准。
- 关闭浏览器后再次进入可恢复。
- 已交卷考试再次进入 `/exam` 时可继续查看复盘。
- 超过截止时间后自动交卷，未答题计错。
- 模拟考不写 `PracticeAttempt`，只写 `ExamAttempt`。

### 7.6 题目管理

P0 使用单页表单：

- 左侧为编辑表单，分为基础信息、题干、选项、解析、发布设置。
- 右侧为实时预览，可折叠。
- 单选题和多选题默认 A-D 空选项，允许增减到 3-6 项；判断题固定 A/B 为“正确 / 错误”。
- 保存草稿只写入当前浏览器本地存储，不创建后端草稿；页面刷新后恢复本地草稿。
- 发布前进行完整校验；校验失败不调用 API，并在页面中上方展示 toast。
- 发布成功调用 `POST /admin/questions`，payload 状态为 `published`。
- 正确答案切换时，选项行保留正确答案高亮并触发短暂动画，不额外显示行内文字提示。
- 实时预览展示当前题干、选项和解析；解析为空时显示“暂无解析”，不使用速记假数据。

导入流程：

1. 管理员上传 JSON 文件。
2. 后端只做结构验证，不立即写入。
3. 前端展示验证报告：可导入数量、失败数量、失败原因。
4. 管理员确认后写入。
5. 任一写入失败则整批回滚。

导出流程：

- 按当前筛选条件导出 JSON。
- 导出内容不包含训练统计、创建时间、更新人等运行数据。

## 8. 模拟考配置

配置文件路径：`backend/config/exam-paper-config.yaml`。

P0 配置粒度为科目级，不按语言和级别拆分。

```yaml
defaults:
  passScorePercent: 60
  shuffleQuestions: false
  shuffleOptions: true

papers:
  programming:
    durationMinutes: 45
    sections:
      - { type: judgment, count: 8 }
      - { type: single, count: 22 }
      - { type: multiple, count: 10 }
  security_privacy:
    durationMinutes: 45
    sections:
      - { type: judgment, count: 8 }
      - { type: single, count: 22 }
      - { type: multiple, count: 10 }
  refactoring:
    durationMinutes: 60
    passScorePercent: 65
    sections:
      - { type: judgment, count: 7 }
      - { type: single, count: 25 }
      - { type: multiple, count: 18 }
```

组卷算法：

1. 根据 `subject` 读取卷面配置。
2. 根据用户选择的 `subject + language + level` 限定题源。
3. 按 section 和题型随机抽题。
4. 题量不足则返回缺口明细。
5. 生成 `ExamAttempt`，保存完整试卷快照。

试卷快照至少包含：

- 生成时的配置。
- 题目顺序。
- 每题的题干、选项、正确答案、解析、速记。
- 用户答题记录。

## 11. UI/UX 设计输入

### 11.1 设计原则

- 这是内部学习和管理工具，不做营销型首页，第一屏必须直接进入可操作界面。
- 使用更有辨识度的蓝紫主题，避免使用绿色作为主色；保留少量蓝、紫、琥珀、珊瑚色用于区分状态和图表。
- 全站字体、标题、侧边栏、功能标题、卡片内容使用统一字号层级，避免同类信息在不同页面尺度不一致。
- 页面布局保持稳定：卡片圆角、边框、阴影、间距、按钮尺寸和表格行高在各模块中保持一致。
- 删除低价值的辅助小标题，例如“内部训练平台”“题库浏览”“复习中心”“题源覆盖”等；保留真正承担功能分组的标题。
- 高频操作减少跳转；筛选、作答、复盘、题目编辑、预览、统计查看应在当前页面完成。
- 页面切换不得以整页 loading 或阻塞式退出动画作为默认反馈；与后端无关的页面必须同步渲染。
- 已成功加载过的数据页再次进入时，优先显示会话内存缓存内容，并以非阻塞方式后台刷新；刷新失败时保留旧数据并提示。
- 动效只用于局部动作反馈和轻量入场，不延迟内容挂载；用户启用 `prefers-reduced-motion` 时应降级。

### 11.2 全局命名与文案

| 类型 | 规则 |
|---|---|
| 科目 | 筛选、编辑表单和管理表单中显示“科目二（编程知识）”“科目三（安全质量隐私）”“科目四（重构知识）”；页面标题和记录摘要可简写为“科目二”“科目三”“科目四”。 |
| 级别 | 所有下拉和摘要均使用“入门级”“工作级”“专业级”。 |
| 题型 | 显示“单选题”“多选题”“判断题”，不额外说明“对错题”。 |
| 题源摘要 | 模拟考、复习记录和最近模拟考优先使用“科目X · 语言 · 级别”的短格式，避免长科目名称挤占空间。 |
| 操作文案 | 题库筛选后的练习入口命名为“按当前筛选练习”，不使用“刷当前筛选集”。模拟考保存按钮命名为“提交答案”，复盘单题结果使用“回答正确/回答错误”。 |

### 11.3 页面与组件要求

| 页面/组件 | 设计与交互要求 |
|---|---|
| 全局主题与动效 | 默认 Light 主题，提供 Dark 主题切换，主题选择写入当前浏览器。全局 token 覆盖字体、颜色、状态、图表、阴影、边框、间距和焦点态。局部组件使用 Motion/CSS 动效增强 hover、focus、active、disabled、loading 和结果反馈，不使用阻塞页面切换。 |
| 页面切换与数据加载 | `AppShell` 不以 pathname 作为整页 key，不使用 `AnimatePresence mode="wait"` 包裹路由 Outlet。`/admin/questions` 这类无 mount-time 后端依赖页面必须直接显示编辑器。`/questions`、`/practice`、`/review`、`/exam`、`/admin/stats`、`/admin/settings` 使用缓存优先状态，非数据工具栏和筛选器始终立即渲染。 |
| 侧边栏 | 导航字体加大，当前页面高亮明确；品牌图标使用简洁盾牌/训练标识，去除 AI 生成感；身份卡只展示当前 IP 和角色，不提示“ALLOWED_CIDR 已命中”。 |
| 首页 | “今日训练”作为主要功能标题，字号大于训练说明。训练日历以“训练日历”为标题，月份切换单独显示“2026 年 5 月”；日历按周一到周日排列，固定渲染 6 周网格，支持不同月份 4/5/6 行数据时页面高度不跳变。 |
| 题库 | 筛选栏使用科目、语言、级别、题型、关键词。题目预览区域加背景框、标题加大、整体宽高扩大；标签与题干、代码块、选项和操作按钮之间保持可读间距。 |
| 练习 | 左侧为单题作答区，顶部提供“练习 / 背诵”模式切换，并在切换按钮右侧展示当前模式说明。题源/进度与题干之间保持可读间距；右侧只保留当前筛选和快速跳题模块。切题按钮使用左右箭头，提交按钮与模拟考保持一致。 |
| 复习 | 顶部仅保留页面标题和右侧标签切换，去除“先处理未掌握错题”等无实际功能文案。错题、收藏、记录标签必须真实切换内容；记录只展示模拟考记录；表格列宽稳定，操作列与表头对齐；分页控件之间保持可读间距；未掌握、已掌握、连续答对状态使用不同颜色。 |
| 模拟考 | 未启动时显示题源选择和“开始模拟考”；主试卷区显示题源短摘要、倒计时、题干、选项和“提交答案”。答题卡区显示总题数、合格线、已答/当前/疑问状态和交卷按钮；复盘时只显示正确/错误图例，并展示考试结果摘要和“重新模拟考”按钮。 |
| 题目管理 | 编辑区与预览区比例稳定。基础字段显示完整科目、语言、级别和题型选项；题干标题为“题干（支持 Markdown 语法）”；题干中代码以 Markdown fenced code 写入并在预览中按代码块高亮渲染；选项每行一个，单选/多选可在 3-6 项内增减，判断题固定 A/B；正确答案勾选后选项行保留高亮反馈；保存草稿和发布按钮固定在表单底部右侧。 |
| 运营看板 | 顶部展示当前题库数量、今日访问用户、今日练习题数、今日模拟考，数据来自真实管理统计接口。下方题库统计与训练统计平分页面。题库统计展示题量分布和基于实际练习记录计算的 Top10 低正确率题目；训练统计拆为三个近 7 天坐标图，分别显示访问用户、练习题数、模拟考，横坐标与柱体严格对齐，并在悬停时把具体数据显示在当前柱体旁边，提示内容不重复日期。 |
| 系统设置 | IP 固定角色管理在上，高风险数据清空在下。角色表必须有表头，角色显示为“系统管理员”“题库管理员”等可读名称，权限列按 `permissionKeys` 展示能力分组，不展示不可单独配置的细粒度权限项。数据清空使用危险色背景和按钮，提示确认短语与审计日志。 |

### 11.4 必备状态页

- `403`：不在允许网段内。
- 空题库：提示联系题库管理员。
- 筛选无结果：提示调整筛选。
- 模拟考题量不足：列出缺少题型和数量。
- 导入验证失败：列出行号和字段错误。
- 权限不足：说明当前角色，不展示不可用操作。

## 12. 安全与运维约束

### 12.1 网络与身份

- 系统仅部署在公司内网。
- `ALLOWED_CIDR` 必填。
- 只支持 IPv4。
- 仅信任配置中的反向代理。
- 所有 API 都执行 IP 白名单校验。

### 12.2 文件上传

P0 支持手动上传图片：

- 允许类型：PNG、JPEG、WebP、GIF。
- 单文件上限：5 MB。
- 存储路径：`backend/uploads/questions/<yyyyMM>/<uuid>.<ext>`。
- 返回 URL：`/uploads/questions/<yyyyMM>/<uuid>.<ext>`。

P0 不做复杂孤儿文件回收；题目归档后图片保留。

### 12.3 数据清空

系统管理员可清空数据，范围限定为：

| 范围 | 说明 |
|---|---|
| `activity` | 练习、错题、收藏、考试记录 |
| `questions` | 题库和题库图片 |
| `all` | 题库、活动数据、角色绑定 |

清空要求：

- 请求必须包含确认短语。
- 后端写审计日志。
- `questions` 或 `all` 会删除题库图片目录。

### 12.4 开发协作与 PR 提交流程

PR 提交属于开发协作流程，不进入产品运行时能力。

- 仓库提供 `scripts/github-pr.ps1`，用于推送当前功能分支、创建 PR，并按需执行 rebase merge。
- npm 入口：`npm run pr:github` 创建 PR；`npm run pr:github:rebase` 创建 PR 后执行 rebase merge。
- 脚本要求当前分支不是 `main/master`，且工作树必须干净。
- 脚本通过临时 `GH_TOKEN` 调用 GitHub API；真实 token 不得写入 `.env.example`、提交记录或 PR 描述。
- `GH_TOKEN` 可从当前 shell 环境读取；若未设置，脚本以隐藏输入读取，并在脚本结束后清理当前进程环境变量。
- 推荐权限：classic PAT 使用 `repo`；fine-grained token 对本仓库至少具备 `Contents: Read and write` 与 `Pull requests: Read and write`。

## 15. 附录：JSON 导入格式（P0）

```json
{
  "version": "1.0",
  "questions": [
    {
      "sourceCode": "optional-source-id",
      "subject": "programming",
      "language": "java",
      "level": "working",
      "type": "single",
      "tags": ["集合", "线程安全"],
      "stemMd": "下面哪个集合是线程安全的？",
      "options": [
        { "key": "A", "text": "ArrayList", "isCorrect": false },
        { "key": "B", "text": "HashMap", "isCorrect": false },
        { "key": "C", "text": "ConcurrentHashMap", "isCorrect": true },
        { "key": "D", "text": "LinkedList", "isCorrect": false }
      ],
      "explanationMd": "ConcurrentHashMap 用于并发访问场景。",
      "memo": "并发集合记 Concurrent 前缀"
    }
  ]
}
```

导入校验：

- `version` 必须支持。
- `questions` 非空。
- 每题组合合法。
- 选项 key 连续且唯一。
- 正确选项数量符合题型。
- Markdown 长度、选项长度、标签数量不超过限制。
- `sourceCode` 如存在则在本次导入内不可重复。
